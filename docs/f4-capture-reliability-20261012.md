# 赛前盘口采集改进（2026-10-12）

本轮处理的是实际采集时机与保存，未改变模型权重、训练门槛、研究通知或投注行为。

## 已核实的原因和来源

10月11日21:00香港时间开球的两场，没有赛前快照。手动守候20:56才启动，而T−15有效窗口已于20:50关闭；不能据此说提供商没有盘口。原记录和真实缺失均保留。

10月12日12:38香港时间的独立来源检查，香港赛马会已发布考文垂—纽卡斯尔（次日03:00开球）。官方赛事50075993与ESPN401879267唯一匹配；亚洲盘与同公司胜平负均在售，当前HTTP响应及缓存通过核查。它是窗口外检查，没有写入正式T180/T60/T15样本。

公开第二源也已调查：ESPN/DraftKings能显示本场及下周末10场的同公司三向及两向Spread，但缺少报价更新时间和受注状态，尚不计入严格有效样本。球探亚盘页面访问失败，InferSports仍声明馈送过期；不能将不同公司共享这一上游称为独立兜底。[详细来源实测和API候选](f4-source-options-20261012.md)列明证据与费用，当前未开通付费源。

## 本轮落实的改进

1. 亚洲盘及同公司胜平负先采集、写入不可变文件，再推送检查点；之后才执行旧胜平负、Titan007、F2。T−15没有旧实验窗口时不请求旧源。混合开球批次中，任何T−15仍缺完整报价时，本轮旧源暂缓，让下一分钟重试。
2. 移除三次缺报价就永久放弃整个窗口的规则。T−15每分钟、其余窗口每两分钟继续重试，严格在窗口关闭时停止；不覆盖首次合格快照，不改旧时间。
3. 首次采集异常有三次有界重试。Git拉取／推送短暂失败也有界重试；遇rebase冲突立即保留现场，禁止暂存冲突文件或强推。
4. 默认在下一个待采时间点的120分钟内开始守候，最多300分钟。单场T180至T15可在一次守候中覆盖，减少日常对任务交接的依赖；多批次和异常情况下仍可能需要接续，也仍可能排队。
5. 每场分别记录T180、T60、T15的有效、待采、重试、尝试无报价、未尝试漏窗及排除状态；同时列出同公司胜平负是否齐全。本次来源检查与全月覆盖分别报告，赛果不能填补盘口缺失。
6. Actions诊断同时备份有限结构化的不可变盘口和赛果，保存14天。正常正式数据仍提交main；若提交失败，这份备份可用于保留原始时间并恢复，不包含供应商整份feed或凭据。

## 验证边界

回归场景包括：旧接口耗时跨窗、混合批次T−15第一次缺盘后恢复、窗口早侧多次缺盘后在最后一分钟恢复、首次请求超时、Git网络故障与冲突、换开球时间和其他实验记录不能掩盖缺失、赛果不能代替报价。

本地441项测试及112个子测试通过。[云端运行38207030533](https://github.com/kimalbert666/football/actions/runs/38207030533)已通过测试、采集检查、main保存及诊断上传，日常通知跳过。下载后的备份含18条不可变盘口，其内容逐条与main一致，日志也在备份中。此次无比赛进入窗口，新增正式样本0；[本轮云端验收](../data/f4/status/capture-repair-acceptance-20261012.json)将启动、保存和未来窗口分别标明。当前已有的18条真实盘口保持原内容，未将探测或缺失改成模型成绩。今晚正式三个窗口能否采齐，应在实际落盘后验收；本次修复不承诺GitHub或数据源绝对零故障。
