# f4 云端并行验证

## 当前运行安排（2026-10-04修订）

f4覆盖**整个英超的赛前亚洲让球研究**，结合同公司胜平负价格。所有实际出现的合法让球档位均可记录；0.25、0.5、1.25只是讨论中的例子。原四队任务、旧胜平负账本保留，各自独立。

- **研究期只发月报和重要故障通知**。试验方向及日常采集留在后台，不发赛前方向邮件。十二月是首次复审目标，不会自动开放推荐，也不保证届时已有足够样本。
- 每小时第7、17、27、37、47、57分钟计划启动检查。如果下一个已知待采集时间点在180分钟内，程序会留在同一次任务中等待、刷新赛程并采集，每次最多持续300分钟；仍有临近窗口时先保存记录，再请求下一次任务接续。没有临近比赛时检查完即退出。
- 保存T−180±20、T−60±10、T−15±5分钟记录，固定以最早有效T−15记录评分。等待任务减少对每次定时触发的依赖，**仍不能保证准点**：GitHub排队、任务接续及数据源均可能延迟；晚到的记录不会倒填为合格快照。
- 香港时间每天07:43计划补赛果和未来一周赛程；等待任务启动时，也会检查是否超过20小时未完成赛果补录并补做。每月1日10:13计划汇总上月；错过月报触发时由后续运行补生成。
- 三个候选：M1盘口／水位及胜平负、M2再加已观察赛果计算的赛前实力评级、M3加入同公司早晚变化。至少120训练／40验证／40测试场才启动时间顺序切分后的拟合；每月一个研究版本。候选不自动晋升，不自动改变线上权重或下注。程序能拟合预先定义的候选，不能自动阅读新论文。

## 赔率来源与独立备用

首选InferSports公开接口，皇冠优先，也可使用配置内的澳门、香港赛马会、Sbobet等已明确识别的公司。ESPN独立核对英超比赛、主客队和开球时间。三向辅助报价和亚洲让球必须来自同一公司；不能把不同公司的变化拼成升降盘。

InferSports缺少可用报价时，程序可尝试**香港赛马会公开网站的独立数据接口**。这条备用来源不经过InferSports，读取同场赛马会胜平负及让球价格；不登录账户，不调用投注接口。只接纳身份唯一匹配、尚未开赛、正在售卖且HTTP快照新鲜的报价。保留原来源故障和备用覆盖情况，备用正常不会把原来源故障抹掉。

各来源保留所有合格替代盘口。赛马会明确给出唯一主盘标记时采用该标记；没有主盘标签时，固定选择两侧价格最接近的一档作比较线，并明确它不是已认证的公司主盘。抓取时间、报价变化时间、事件时间与来源身份分别保存。供应商报告的初盘与程序首次观察分开；赛马会直连没有验证过的初盘字段时留空，不伪造。

InferSports免费来源声明90秒延迟，其`stale=false`及全局健康状态仅为供应商声明。赛马会备用还检查当前响应、缓存期限和售卖状态；这些检查也不保证用户可以按该价格成交。数据缺失必须显示为缺失，不能写成“没有合格选项”。

**截至10月4日的来源检查：**赛马会独立接口实际返回了可解析的胜平负和让球资料，当时未发布可匹配的英超盘，因此只完成接口与字段验收。真实英超“窗口采集→赛果回填→评分”仍须等待比赛。10月4日检查还发现InferSports的实时馈送停滞；该外部问题须看最新来源状态，不能从备用接口接通或Actions绿勾推断已经恢复。

## 怎样查看和使用

平时无需发命令，也不需要打开GPT或GitHub网页。已启用的GitHub Actions执行Python程序，不调用付费模型API。

- 看最新记录：[f4最新报告](../data/f4/reports/latest.md)、[亚盘状态](../data/f4/ah/latest.json)、[通知Issue](https://github.com/kimalbert666/football/issues/1)。只有月报及重要故障按当前策略发布到Issue；新预测或新赛果不会单独触发邮件。
- 看是否执行：仓库顶部 **Actions → F4 Shadow Monitor**。绿勾只表示程序完成，还需查看摘要中的赔率来源健康和有效样本数。
- 手动检查：**Run workflow → main → all**，补数据、补结果并生成报告；不会补造已经错过的赛前预测。`watch`会执行有时长限制的等待与采集，在没有临近窗口时直接结束。
- 亚盘原始资料：[快照](../data/f4/ah/observations)、[开球批次](../data/f4/ah/batches)、[研究版本](../data/f4/ah/research)。目录在首次有相应数据后出现。旧胜平负资料仍保存在`data/f4/predictions/`、`outcomes/`、`evaluations/`。

没有比赛进入窗口时，零新增样本是正常状态。收集已完赛比分不等于产生了赛前预测；不同盘口、不同窗口也不能当作不同比赛累加独立样本。

## 月报覆盖统计与九月更正

月报分别列出：上线前窗口已经结束、延期或取消、首次发现晚于采集窗口、发现时间未知，以及上线后及时发现且应采集的比赛。只在最后一类中区分有效T−15记录、尝试后缺报价和未留下尝试的漏窗。已知赛程覆盖不是完整赛程的保证。

原九月月报把9场上线前的比赛算成“缺报价／漏窗”。现已核对：这9场均早于9月23日的亚盘研究起点；已知九月赛程中，应采集0场、缺报价0场、漏窗0场。**这纠正统计口径，不增加任何预测或命中成绩。** 原报告原样保留，更正另见[九月月报更正说明](../data/f4/reports/monthly-2026-09-correction-20261004.md)。

月报收益为按原快照盘口和价格计算的模拟结算，全赢／半赢／走盘／半输／全输分别报告，不以走盘或半赢冒充全赢。不执行真实投注。

## 旧胜平负实验的边界

旧账本与新增亚盘研究分开。旧实验对球探公开页面转载的皇冠90分钟胜平负报价去水，保存市场参考；冻结的旧Dixon–Coles参数及可准确匹配的f2比分点预测作为独立候选。旧参数不重新拟合，训练日期只具备历史文件声明，未经独立认证；f2外部模型不能由本仓库重训，比分点预测不转换为虚构概率。

旧实验保留T−180、T−60各±20分钟的历史口径，不能与新的亚洲让球窗口混算。首次有效市场快照固定后，缺少候选时不事后换成更有利的时点。市场参考不是已验证的真实胜率或可下注优势。原每周复审描述只涉及旧评分程序，**当前f4不发送每周邮件**。

## 保存和排错

正式记录提交在本仓库`data/f4/`中，等待任务在采集后保存检查点；Actions短期诊断另保留14天。当前仓库公开，有限结构化记录和分析可被公开查看；凭据及整份供应商原始数据不写入公开仓库。

数据源失败、身份无法匹配和遗漏窗口分别保留状态；执行错误必须报错，尽量保存已经完成的记录。等待接续不能承诺消除所有漏采。完整真实比赛生命周期必须由未来比赛验证，模拟测试不能替代前向成绩。
