# f4 云端并行验证

f4是数据核验、预测记录与比较流程。当前云端版本与原来的四队任务并行，范围为**整个英超的比赛**；杯赛暂不纳入这个实验。

## 怎样使用

平时无需发命令，也不需要打开GPT或GitHub网页。已经部署并启用的GitHub Actions会运行Python程序；它不调用付费模型API。

- 看最新说明：[f4最新报告](../data/f4/reports/latest.md)。有新预测、赛果、周报或重要数据状态变化时，会更新题为 **[f4] 英超并行验证** 的Issue。
- 看是否执行：仓库顶部 **Actions → F4 Shadow Monitor**，打开一次运行查看摘要及数据提醒。
- 手动检查：在该工作流页面点 **Run workflow**，选择`main`和`all`。它会收集当前数据、补已完赛结果并生成报告；不会补造已经错过的赛前预测。
- 回看原始记录：[赛前快照](../data/f4/predictions)、[赛果修订](../data/f4/outcomes)、[评分](../data/f4/evaluations)。相应目录在首次有数据后出现。

报告中的“仅作市场参考”不是可下注选项，也不是已经验证的模型优势。没有比赛进入记录窗口时，不会为了产生通知而虚构预测。数据源失败、没有匹配赔率、遗漏窗口会在报告中说明；运行绿勾只表示程序完成，仍需看数据健康状态。

同一场比赛的两个窗口分别评分，不能当成两场独立比赛累加样本。扩大联赛范围提高采集速度，并不保证命中率提高；模型缺少的球队参数也会明确记缺失。

## 是否需要先训练、重新分配权重

**这次不需要。先固定版本，积累真实对照。**

| 部分 | 当前做什么 | 是否自动训练／改权重 |
|---|---|---|
| 市场参考 | 对球探转载的同场皇冠胜平负报价去水，保存主／平／客概率 | 不训练；不是独立模型优势 |
| f3模型候选 | 对已冻结的旧Dixon–Coles参数生成独立概率，与市场同场比较 | 不重新拟合，权重0；训练日期只具备旧模型声明，未独立认证 |
| f2外部预测 | 在窗口内请求可匹配的赛前比分点预测，记录方向与缺失 | 外部模型不能由本仓库重新训练；不把比分转成虚构概率 |
| f4复审 | 核对同场命中率和概率误差、缺失与覆盖率 | 不自动选权重，不自动晋升候选 |

以后若比较支持改进，才另外定义训练、选参、最终测试区间，研究新模型和权重。100场是观察节点，不是成功保证；看过测试结果后再改参数，需要新的未来区间验证。

本地f4第一轮历史探索未选出可靠优于市场的候选，所以当前不强行融合。这个影子实验采集的是新增真实记录，不能把旧记录补造时间戳当成新成绩。

## 运行安排与边界

- 每小时第11、41分钟检查一次赛程和赔率。
- 赛前记录窗口为开赛前180分钟、60分钟，各允许偏差20分钟；实际时差逐条保存。GitHub可能延迟，漏窗时如实记缺失。
- 每天香港时间07:43补赛果、检查未来一周赛程；未完赛、延期、取消、比分更正分别处理。
- 每周二香港时间10:13汇总固定模型表现。**这是程序评分复审，不是模型自动阅读论文。** 自动研究新论文另需可运行的Codex／模型API环境，目前未接入。
- 当前使用ESPN赛程／完赛状态与球探公开页面转载的皇冠90分钟胜平负报价，逐次检查身份和时点；不以体彩或其他公司报价兜底。皇冠初盘、即时盘分开，实际抓取时间与提供商更新时间均保存。此页面不是皇冠官方API，也没有独立受注状态，所以报价只作研究参考，不能保证可成交。没有独立赛程核验时，覆盖率会降级。
- 每个预测快照独立保存；赛果修订另存。每个窗口固定取最早有效市场记录进行比较；那条记录缺候选时，不事后换更有利时点补配。
- 模型文件和实验参数有固定哈希；新增数据不会自动改模型，也不执行下注。

## 保存和排错

赛前、赛果与评分资料提交在本仓库`data/f4/`中；短期诊断日志另保留14天。当前仓库公开，因此这些有限的预测和结果记录也可被公开查看；没有API密钥写入仓库。

若工作流失败，打开红色步骤看错误。失败前已完成的f4记录会尽量保存，错误不会被伪装成预测成功。原四队监控、旧每周预测继续使用各自流程；其中每周校验缺引号的问题已单独修复。
