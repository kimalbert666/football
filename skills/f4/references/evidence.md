## 当前实现的待修正点

| 原文件/状态 | 静态审查发现 | f4要求 |
|---|---|---|
| `engine/cache/f2_fusion.json` | weight=0、matchedSamples=0、status=collecting | 外部点预测保持研究状态；100场不是证实提升 |
| `engine/scripts/f2_fusion.py` | load_pairs未强制抓取早于开赛；匹配丢失时区/时间；使用p_final作为基线 | 存证时间+统一UTC+固定窗口；保存未融合基线，隔离不确定旧样本 |
| 同一文件`combine` | 非零weight是对某方向加logit，不是按百分比混合 | 参数文档写真实含义，实验后确定，禁止说“f2占30%” |
| `engine/scripts/calibrate.py` | 同一批样本网格寻优并评价；缺市场概率时用p_final替代 | 训练/验证/最终测试分开，市场缺失不能用模型冒充 |
| `engine/scripts/four_team_monitor.py` | grade B主要检查insight文件是否存在；early/final会upsert同一条 | 验证内容新鲜度与字段；每阶段不可变快照 |
| 同一脚本与workflow | `notify`依据是否有到期比赛，不是只依据候选合格 | 现有Issue也可能显示“跳过”。不能向用户保证每条Issue都有合格选项 |
| `.github/workflows/four-team-monitor.yml` | 旧日结调用run.py verify，其中包含自动校准；旧流程的名字不等于只读验证 | 新设计拆分日常回填与候选研究；未经验证不自动改线上权重 |
| `engine/scripts/run.py` | sh用check=False且没有汇总失败返回 | 新流程把数据错误/步骤失败暴露为失败状态，绿勾不能替代有效数据检查 |
| f3部分手动修正/画像 | 文字经验、固定乘子、用户反馈升级证据等不等于因果证据 | 作为有版本的待测特征；不能凭叙述更改概率或证据质量 |

这里是改进要求与部署前核对项；本次只创建f4及离线评分器，没有声称这些生产代码已修复。

## 证据等级

- 文档/代码审计：能确认某段代码的行为和数据限制，不证明模型效果。
- 历史探索结果：有回测数字，但无完整时点/试验隔离，不作为前向保证。
- 独立时间外测试：需要原始预测、未污染的训练、封存评估和同场对照。
- 真实前向验证：在未来比赛前落盘，赛后仅补结果；这是最终判断f4是否值得升级的依据。

截至审计日，新f4处于第一层并有离线评分工具；后两层尚无f4有效样本。不得把脚本测试通过写成预测准确率验证通过。

## 2026-09-19：本地历史探索已运行

实验`f4-historical-exploration-v1`在9月16日固定时间切分与候选，9月19日首跑前固定实现与哈希。使用五大联赛2024/25和2025/26部分赛季本地缓存2,654场，全部有有效结果与b365c三向赔率；初始历史452、训练366、验证546、后段测试388、下一赛季902。没有f2历史赛前输出或xG，报价原始时点也未认证，因此只作为第二层历史探索证据，不是严格临场或前向样本。

预定选择规则选出`market`。其验证命中率53.11%，后段测试216/388（55.67%），下一赛季484/902（53.66%）。市场+Elo修正的正则10版本验证多对1场，但RPS相对恶化1.21%，超过事先1%门槛；正则100版本过概率门槛但验证少对2场，未取代市场。

正则100融合在后段测试216/388、下一赛季485/902。下一赛季相对市场仅+0.11个百分点，按20个来源日期周配对重采样的95%区间约−0.89至+1.22个百分点，未排除无改进；RPS差的区间也包含0。没有根据测试段表现重新选参或升级生产权重。此结论仅涉及本次有限候选，不能扩大为“市场永远最强”。
