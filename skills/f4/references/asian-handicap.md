# 亚洲让球专项（2026-09-23）

用户要的是可复用、可检验的盘口条件规则。覆盖所有实际出现的0.25步长盘口，正负／平手盘均支持，不将举例盘口当限制。

## 数据及比较

- 全英超，90分钟含补时。M1盘口与水位、M2增加赛前实力评级、M3增加同公司早期至临场的变化。每个盘口单独报告样本；先共享统计模型，不因几场样本建立独立“稳赢规则”。
- 用户已允许其他公司。当前适配器使用InferSports公开免费接口，默认皇冠、澳门、香港赛马会、Sbobet顺序，只使用明确公司身份的实际报价；配置未出现或接口没提供的公司不能宣称接入。
- ESPN核对比赛身份、主客队和开球时间。保留公司的每个合格替代盘口；没有主盘标签时，固定以两边价格最接近的盘口作为比较线，明确它不是已认证的公司主盘。M3中的变化相应只是固定选线规则下的变化。
- 公司来源进入模型特征；不同公司的早晚报价不能拼成升降盘。三向辅助价格也要求同公司。不同盘口及窗口不是额外独立比赛。
- 开盘字段为提供商报告的初盘，不能称独立认证的真正最早报价；自己首次抓到的快照另记。来源免费档声明90秒延迟。区分抓取时间、报价变化时间、事件更新时间与全局数据源健康；接口stale=false且全局健康新鲜也仅是提供商声明，不是直连博彩公司确认。
- 网络、身份、时间或报价校验失败则保留缺失，不能把数据缺失写成“没有合格选项”。不绕过访问控制，不开通付费服务，不公开整份供应商原始feed。

## 训练、记录及通知

- `engine/scripts/f4_ah.py`记录T−180／T−60／T−15分钟，允许偏差分别20／10／5分钟；记录实际时差。T−15最早有效快照为固定评分口径，不能用赛后或更晚窗口替换。
- `f4_ah_research.py`有正则多分类候选训练、训练/验证/测试时间切分和季度盘完整结算。当前最小样本为训练120、验证40、测试40；样本或特征不足明确`insufficient_data`。这些阈值是启动训练门槛，不是优势证据。
- 每个自然月生成一个研究版本。历史测试报告是探索性成绩，真正前向成绩只能来自模型创建之后落盘的预测。候选不自动晋升、不改变线上权重、不自动下注，也不会在十二月自动启用方向通知。
- `data/f4/ah/`保存真实快照、同开球时段批次、研究版本及来源状态。结算区分全赢、半赢、走盘、半输、全输，每次使用原快照盘口与价格。月报不能以半赢／走盘冒充全赢。
- 研究期只发月报和重要故障，试验方向后台保存；月报在每月1日汇总上月，原四队任务独立。未来经证据验收开启方向通知时，用户只要每批约T−15分钟的一封最终结果，不要T−60初筛邮件。当前方向通知仍关闭。
- GitHub Actions每10分钟目标检查，实际可能延迟；漏窗如实记录，不能承诺准点送达。程序月度训练不等于GPT持续读论文；后者仍需另有可运行的模型环境。

上线与真实采集情况必须看最新Actions及`data/f4/ah/latest.json`，不能从本说明、测试通过或网站可访问推断已采到赛前样本。
