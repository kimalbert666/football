# 云端接入与持续更新

用户选择新 f4 与原 f2/f3 任务并行，先保存真实对照，不替换旧系统。用户仓库为 [kimalbert666/football](https://github.com/kimalbert666/football)。实际部署验收与使用入口见仓库的 [f4 云端说明](https://github.com/kimalbert666/football/blob/main/docs/f4-cloud.md)；回答“现在是否在运行”前检查最新 Actions 记录及报告中的数据健康状态，不能仅从文件存在或绿勾推断预测有效。

## 实现入口

- skill 本身在 `skills/f4/`，供模型阅读；GitHub Actions 执行 `engine/scripts/f4_cloud.py`，不会自动调用语言模型阅读 skill。
- `.github/workflows/f4-shadow.yml`：每小时第 11、41 分钟检查，香港时间每天 07:43 补赛果，周二 10:13 生成固定模型对照周报。
- `data/f4/config.json` 固定实验、赛前窗口和模型哈希；范围设置为整个英超；旧四队配置继续只供原任务使用，杯赛不在 f4 实验范围内。
- `f4_sources.py` 获取 ESPN 赛程、常规完场结果；`f4_crown.py` 读取球探公开页面转载的皇冠90分钟三向报价。用户已要求皇冠，不能偷偷用体彩或别家公司兜底。未知身份、数据失败和覆盖缺口保留状态，转载报价不等于可成交的官方直连报价。
- `f4_candidates.py` 使用冻结的旧 DC 参数，另记录能准确匹配的 f2 比分点预测；不训练、不将比分直接换成概率。
- `f4_ledger.py` 保存不可变赛前快照与独立赛果修订，按同场、同窗口、同版本评分。`data/f4/reports/latest.md` 是人读入口。

当前候选权重为 0。市场只作参考，不表示真实胜率或可下注优势。旧模型训练日期只有文件声明，未经独立认证。T−180 分钟与 T−60 分钟各允许 ±20 分钟；保存实际决策时间，迟到或漏窗不能补造。

## 日常记录、每周复审与训练

日结只补数据；每周任务只重新评分与检查数据质量，不自动调参、晋升模型或研究论文。之后的权重研究需要单独定义训练、选参和独立测试区间；不能在看到测试结果后反复调参并沿用同一测试成绩。

本 skill 的 `scripts/evaluate.py` 是严格 JSONL 离线评分器，`scripts/replay.py` 是本地历史探索工具，均不同于上述云端账本入口。云端数据不能未经 schema 转换就交给旧离线评分器，也不能导入原系统缺少真实截止时间的记录冒充前向样本。

GitHub Python 工作流可在 GPT 和网页关闭后运行。程序评分不需要模型 API；阅读新研究需要可运行的 Codex 或模型 API 环境，当前未接入。如果用户另要求创建 Codex 定时任务，使用 automation_update 检查并创建或更新，不能把本地任务说成无需电脑的 GitHub 云端任务。

## 保存和通知

正式记录提交于 `data/f4/`，与旧系统目录分开；Actions 临时诊断保留 14 天。新预测、赛果、周报或重要数据健康变化才更新 `[f4] 英超并行验证` Issue；不把单源市场参考称为合格投注选项。

当前仓库公开，只保存有限结构化数据、提供商元信息和自己的分析，不公开凭据或原始新闻正文。执行失败必须报错，尽量保存已完成快照。实际完整比赛生命周期须等真实未来比赛完成才能验收；模拟测试不能代替前向成绩。
